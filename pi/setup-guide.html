SengledTools · Raspberry Pi

Run your lights from a Raspberry Pi

The Pi becomes the always-on server for your bulbs. It hosts a private Wi-Fi network just for them, runs the bulb service and web app, and connects to your building's network with an Ethernet cable. Your Mac no longer has to stay on or switch networks.

Your details

Every command below updates as you type, so you can copy them as-is. Nothing leaves this page, and the password is never saved.

1

Get the parts

  • Raspberry Pi 4 or Pi 5, 4 GB or more2 GB works, but building the web app on it is slow and can run out of memory. Older models (Pi 3, Zero) aren't enough.
  • The official power supply for that modelPi 5: 27 W USB-C. Pi 4: 15 W USB-C. Phone chargers often cause random restarts.
  • microSD card, 32 GB or moreAny name brand marked A1 or A2. Your Mac needs an SD slot or a USB card reader to write it.
  • Ethernet cableLong enough to reach a network jack in your unit. You'll check that the jack is active in step 3.
  • A case (optional)For a Pi 5, pick one with a fan or the official active cooler.
  • Monitor and USB keyboard (only if something goes wrong)Pi 4 and 5 use a micro-HDMI cable.
2

Put Raspberry Pi OS on the microSD card

  1. On the Mac, download and install Raspberry Pi Imager from raspberrypi.com/software, then open it.
  2. Device: choose your Pi model.
  3. Operating system: Raspberry Pi OS (other) → Raspberry Pi OS Lite (64-bit). “Lite” has no desktop, which the Pi doesn't need and which saves memory.
  4. Storage: the microSD card. Double-check it's the card, because it gets erased.
  5. When Imager offers to customise the OS (“Edit settings” in older versions), use these settings:
    Hostnamelights
    Username and passwordnate and a password you'll remember. You'll type it to log in.
    Time zone and keyboardYours
    Wi-FiLeave it off. The Pi's Wi-Fi will host the bulbs' network, and the Pi uses Ethernet for the building.
    SSHTurn on, with password authentication
    Raspberry Pi ConnectOptional. If it's offered, it gives you a backup way to open the Pi's terminal from a browser.
  6. Write the card (about 5 minutes), then eject it.
3

Plug in the Pi and connect to it

  1. Put the card in the Pi, connect the Ethernet cable from the wall jack to the Pi, and only then plug in the power. Wait about 2 minutes. The first boot takes longer and may restart once.
  2. On the Mac, open Terminal (⌘ Space, type “Terminal”) and connect to the Pi:
    Mac · Terminal
    ssh nate@lights.local
    The first time, it asks “Are you sure you want to continue connecting?”. Type yes. Then type the Pi password. Nothing shows while you type, which is normal. You're in when the prompt looks like nate@lights:~ $.
  3. Check that the Pi has internet through the wall jack:
    Pi · in the SSH window
    ping -c 3 raspberrypi.com
    You want to see 3 received. That means the jack is active and the installer can download what it needs.
Good sign If SSH worked while your Mac was on WhiteSky Wi-Fi, the building lets Wi-Fi devices reach wired ones. Your phone will be able to open the web app directly.
“Could not resolve hostname” or it just hangs

Wait another minute and try again. If it still fails, the building network may not pass the .local name around.

  • Plug a monitor and keyboard into the Pi, log in, and run hostname -I. The first address is the Pi's. Then on the Mac, run ssh nate@THAT-ADDRESS, and use that address wherever this guide says lights.local.
  • If hostname -I shows nothing, the wall jack isn't active. Ask WhiteSky to turn it on. They may ask for the Pi's hardware (MAC) address, which cat /sys/class/net/eth0/address shows.
  • If the Pi has an address and internet but the Mac still can't reach it, the building keeps wired and Wi-Fi devices apart. On the Pi's own keyboard, do step 8 (Tailscale) first, using sudo tailscale up --qr and scanning the QR code with your phone to sign in. Then put Tailscale on the Mac too, and use lights instead of lights.local everywhere.
4

Copy SengledTools to the Pi

Your version of the tools, with the web app and all recent fixes, only exists on your Mac, so copy it over.

  1. On the Pi, install the copy tool:
    Pi · in the SSH window
    sudo apt update && sudo apt install -y rsync
  2. Open a new Terminal tab on the Mac (⌘ T), not inside the SSH session, and copy the folder. It skips the Mac-only parts, which the Pi rebuilds for itself.
    Mac · new Terminal tab
    rsync -av --exclude .venv --exclude node_modules --exclude .next --exclude __pycache__ --exclude .git ~/SengledTools/ nate@lights.local:SengledTools/
  3. Optional: bring over your bulb names (like “Side Living Room”) so they carry over:
    Mac · same tab
    ssh nate@lights.local mkdir -p .sengled && scp ~/.sengled/lan.json nate@lights.local:.sengled/
5

Run the installer

Back in the SSH window, run the installer:

Pi · in the SSH window
cd ~/SengledTools && bash pi/install.sh

It asks three questions partway through:

  • Country code: e.g. US. This sets the legal Wi-Fi channels.
  • Name for the bulbs' Wi-Fi: press Enter for SengledNet, or type the name from Your details.
  • Password: 8–63 letters and numbers only (bulbs can choke on symbols). Nothing shows while you type. Use the same one as in Your details.

It takes 10–20 minutes, mostly building the web app. Here's what it does:

  1. Installs system packages and Node.js
  2. Sets up the bulb service's Python packages
  3. Builds the web app (the lighter production build)
  4. Turns the Pi's Wi-Fi into SengledNet (2.4 GHz, WPA2), with the Pi at 10.42.0.1
  5. Sets up a service that starts everything at boot and restarts it if it ever crashes

It ends like this:

✓ Running, and starts by itself after every reboot

All set.

  Web app:     http://lights.local:3000   or   http://100.110.x.x:3000
  Bulb Wi-Fi:  SengledNet  (server address for bulbs: 10.42.0.1)
Check Your phone's Wi-Fi list should now show SengledNet. Don't join it. It's just for the bulbs.

You can run the installer again anytime, for example after copying a newer version. It keeps the Wi-Fi network you set up.

6

Open the web app

On your Mac or phone (on WhiteSky Wi-Fi), open:

Browser address bar
http://lights.local:3000

It's the same app as on your Mac, now served by the Pi. There are no bulbs yet, or your copied names show as offline, until you move them in the next step.

  • If the name doesn't load, use the address the installer printed, like http://100.110.x.x:3000.
  • If neither loads, the building separates wired and Wi-Fi devices. Step 8 gets around that.
  • On iPhone: Share → Add to Home Screen makes it open like an app.
7

Move each bulb to the Pi

Each bulb is paired once, from the Pi. Do one bulb at a time.

  1. Put the bulb in setup mode. If it still works in the web app, select it and go to Advanced → Factory reset (type RESET). Otherwise, flick its power off and on 5+ times, quickly, until it flashes.
  2. On the Pi, run:
    Pi · over SSH
    bash ~/SengledTools/pi/pair-bulb.sh
    It finds the bulb's Sengled_Wi-Fi Bulb_… network, pauses SengledNet for about 20 seconds (the other bulbs reconnect by themselves), gives the bulb SengledNet's name and password, and waits for it to connect.

    It ends with:

    ✓ Joined 'SengledNet'
✓ Connected to the Pi at 10.42.0.214 - it's in the web app now (7C:87:CE:AC:EF:B8).
    If it finds nothing, it says how to put the bulb in setup mode and waits for you to press Enter to look again. If several bulbs are in setup mode, it asks which one.
  3. In the web app, click the ✎ next to the new bulb to name it. A bulb you paired before keeps its name.
From the Mac instead Join the bulb's Sengled_Wi-Fi Bulb_… network from the Wi-Fi menu (it has no password), then:
Mac · Terminal
cd ~/SengledTools && python3 sengled_ctl.py wifi --ssid "SengledNet" --password 'YOUR-PASSWORD' --callback 10.42.0.1
Don't use Wi-Fi setup in the Pi's web app: it expects the computer running it to join the bulb's network.
Range The Pi's built-in Wi-Fi reaches about a room or two. In the Pi's web app, open a bulb's Stats for nerds. A signal of −67 dBm or better is good. If one says weak, move the Pi closer to the middle of your place.
8

Control from anywhere optional

Tailscale (free for personal use) links your devices privately. You can open the web app from your phone on cell data or away from home, no matter how the building network is set up.

  1. Install it on the Pi:
    Pi · in the SSH window
    curl -fsSL https://tailscale.com/install.sh | sh && sudo tailscale up
    It prints a login link. Open it on the Mac and sign in (Google, Apple and others work).
  2. On your iPhone, install Tailscale from the App Store, sign in with the same account, and turn it on.
  3. Open this from anywhere:
    Browser address bar
    http://lights:3000
Don't open it to the internet The web app has no login. Never set up port forwarding for it. Tailscale keeps it visible only to your own devices.
9

Day to day

  • Nothing to start. After a power cut the Pi boots, starts everything, and the bulbs reconnect within about a minute.
  • Your Mac is free. You no longer need to run npm start on it. Stop it if it's still running.
  • Turn the Pi off safely before unplugging it. Wait for the green light to stop blinking:
    Pi · over SSH
    sudo shutdown -h now
  • After changing the tools on the Mac, run the step 4 copy command again, then:
    Pi · over SSH
    bash ~/SengledTools/pi/install.sh
    If only sengled_ctl.py changed, a restart is enough:
    Pi · over SSH
    sudo systemctl restart sengled-lights
  • Watch things connect. Lists what's on the bulbs' Wi-Fi, then shows live as devices join, bulbs check in and connect, and commands go out:
    Pi · over SSH
    bash ~/SengledTools/pi/watch.sh
  • Logs. The first shows the service; the second shows what the bulbs do (the same log as on the Mac):
    Pi · over SSH
    journalctl -u sengled-lights -f
    Pi · over SSH
    tail -f ~/.sengled/logs/sengled.log
    Press Ctrl C to stop watching.

Troubleshooting

The installer says “No Ethernet connection”

Check that the cable is firmly in both ends and that the jack is active (step 3's ping test). The Pi's Wi-Fi is about to become the bulbs' network, so the installer won't continue without Ethernet.

The installer says you're connected over the Pi's Wi-Fi

That step takes over the Wi-Fi, which would cut off your session. Reconnect with the Ethernet address it prints (ssh nate@100.110.x.x) and run it again.

The web app build stops with “out of memory” or “Killed”

This happens on 2 GB Pis. Run the installer again; it picks up where it left off and stops the running service to free memory. If it keeps failing, a 4 GB Pi avoids it.

“SengledNet” doesn't show up in Wi-Fi lists
Pi · over SSH
sudo rfkill unblock wifi && sudo systemctl restart hostapd

If it still doesn't appear, journalctl -u hostapd -u sengled-ap-net -n 30 shows why. Running the installer again also recreates the network, keeping its name and password.

A Mac or iPhone says “SengledNet” could not be joined

Pis set up by an earlier version of the installer host the network with NetworkManager, which Apple devices can't join on a Pi 3. Get the latest tools onto the Pi (git pull, or the copy command from step 4), then move the network to hostapd. It keeps the same name and password, so the bulbs don't notice:

Pi · over SSH
cd ~/SengledTools && bash pi/bulb-wifi.sh
A bulb never shows up in the Pi's web app
  • Its “Sengled Wi-Fi Bulb_…” network came back: it couldn't join. Check the network name and password (case-sensitive) and that the bulb is within range of the Pi, then repeat step 7.
  • See whether it joined the Pi's Wi-Fi. Each connected device is one line:
    Pi · over SSH
    sudo iw dev wlan0 station dump | grep Station
  • See whether it contacted the Pi:
    Pi · over SSH
    grep call-home ~/.sengled/logs/sengled.log | tail
    If it joined but never called home, it was probably paired with the wrong server address. Pair it again with --callback 10.42.0.1.
A bulb that worked stopped responding
  • Turn its switch off, wait 10 seconds, and turn it on. Once, slowly: flicking it quickly several times resets it. Within a minute it should rejoin. Watch for it with:
    Pi · over SSH
    bash ~/SengledTools/pi/watch.sh
  • Still missing after 2 minutes, or flashing? It has lost its Wi-Fi settings. Pair it again from the Pi. It keeps its name in the web app:
    Pi · over SSH
    bash ~/SengledTools/pi/pair-bulb.sh
    If it says no bulb is in setup mode, reset the bulb (5+ quick flicks until it flashes) and press Enter.
The web app says “Bulb service not running”
Pi · over SSH
sudo systemctl restart sengled-lights; journalctl -u sengled-lights -n 50

The last lines usually say what went wrong.
